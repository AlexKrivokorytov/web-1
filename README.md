# Лабораторна робота № 6

## Запуск і перевірка

```bash
npm install
npm run dev
npm run build
npm run preview
```

`npm run dev` запускає локальний сервер розробки. `npm run build` збирає три HTML-сторінки в `dist`, а `npm run preview` запускає локальний сервер для перевірки зібраного сайту.

## Структура проєкту

- `index.html`, `about.html`, `contacts.html` — вміст сторінок.
- `src/main.js` — точка входу, яка підключає головний SCSS-файл.
- `src/styles/` — стилі, поділені на `abstracts`, `base`, `layout` і `components`.
- `src/partials/` — спільний HTML-каркас, шапка, бокова панель і підвал у форматі Handlebars.
- `src/assets/images/` — зображення, які обробляє Vite під час збірки.
- `vite.config.js`, `postcss.config.cjs`, `.browserslistrc` — налаштування Vite, PostCSS і цільових браузерів.

## Контрольні питання

1. `package.json` містить інформацію про проєкт, залежності та npm-команди. `package-lock.json` фіксує точні версії встановлених пакетів і їхніх залежностей, щоб відтворювати встановлення.
2. У SemVer діапазон `^` дозволяє оновлення без зміни першої ненульової частини версії, а `~` — оновлення лише patch-версії в межах тієї самої major- і minor-версії. Наприклад, для `^1.2.3` дозволені версії від `1.2.3` до `менше 2.0.0`, а для `~1.2.3` — від `1.2.3` до `менше 1.3.0`.
3. Vite читає конфігурацію з `postcss.config.cjs`, де підключено Autoprefixer. `.browserslistrc` задає браузери, які потрібно підтримувати; Autoprefixer додає CSS-префікси відповідно до цього списку.
4. Sass/SCSS дає змогу ділити стилі на модулі, використовувати змінні та повторно застосовувати код. Sass-змінні `$var` обробляються під час компіляції. CSS-змінні `--var` залишаються у згенерованому CSS і можуть змінюватися залежно від каскаду, теми чи медіазапитів.
5. `@use` підключає SCSS-модуль для використання його в поточному файлі. `@forward` передає вміст модулів далі, наприклад через спільний файл `_index.scss`.
6. HTML partials — це частини розмітки, які можна повторно підключати на різних сторінках. Вони зменшують дублювання: спільний код зберігається в одному місці й оновлюється централізовано. Це відповідає принципу DRY (Don't Repeat Yourself).
